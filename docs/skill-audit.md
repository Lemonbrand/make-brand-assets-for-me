# What We Learned From The Old Skills

The starting point was four strong workflows: make one object, make one scene, make one matching set, and add small motion.

They already knew the hard parts. They checked the library before drawing, gave every visible part a source, compared work with three approved examples, protected copy space, and kept motion faithful to the still image.

## What was already good

| Good idea | Why it matters | Where it lives now |
| --- | --- | --- |
| One asset has one job | People can tell what it means quickly. | Make One Brand Asset |
| One scene has one story | A website image does not become a pile of unrelated objects. | Make A Brand Scene |
| A framework becomes separate pieces | Each stage can be reused without cutting up a master picture. | Make A Brand Asset Set |
| Reuse approved artwork first | The brand stays recognizable and less work is wasted. | All making skills |
| Name the source of every part | A reviewer can see what was reused, changed, or made new. | The asset receipt |
| Compare with three anchors | “Looks right” has visible evidence. | CHECK |
| Keep the copy zone truly empty | Shadows and texture cannot quietly cover the headline area. | Make A Brand Scene |
| Animate the original pixels | Motion does not turn a tactile illustration into a generic vector icon. | Make A Brand Asset Move |

## What stopped the old workflows from being a product

1. They named one private brand and its internal libraries directly.
2. A new customer had no first step for turning their own references into rules.
3. The language assumed the operator already understood terms such as source maps, canonical anchors, and semantic jobs.
4. The four workflows had no shared receipt, release check, clean-room scan, or installable plugin wrapper.
5. There was no public baseline proving the same method could handle very different art directions.

## What changed

- We added **Set Up My Brand** before any image-making skill.
- We renamed the technical ideas in plain language, while keeping the rigorous checks underneath.
- Every skill follows `SHOW > PLAN > MAKE > CHECK > SAVE`.
- Every skill uses the host's structured ask-user function only when a missing choice changes the result.
- Brand rules, prompts, output paths, checks, and decisions can be saved as portable files.
- Private names, links, local paths, and customer artwork are not part of the package.
- Ten fictional baselines now test three visual styles, three scenes, and one four-piece family.

## Honest baseline result

The baseline proves routing, style switching, scene layout, transparent cutouts, family consistency, prompt receipts, and review-sheet generation.

It is not a claim that every first generation is production-ready. The automated PNG check found that several generated transparent cutouts reach a canvas edge. A real job should revise those files until their padding matches the brand recipe. The three scene tests have useful right-side copy fields, but the copy-zone check should still run at the final website size.

That is the point of the package: it keeps a draft a draft until CHECK says it is ready.
